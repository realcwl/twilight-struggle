# Localization

The globe button in the lobby and below the in-game timeline offers English, Español and 中文.
The preference is browser-local (`coldwar.language.v1`). `?lang=en`, `?lang=es` and `?lang=zh`
override it, including when opening a shared room. Each player can use a different language.

Switching reloads the presentation. Online games reconnect with the same seat credentials and
restore the server's pending prompt. Solo and tutorial games wait for a saved action boundary
if an action is in progress, then reload their own checkpoint. Choosing the current language
cancels a queued change. Game state, room credentials, card IDs, RNG and AI observations do not
depend on the language. User chat is neither translated nor interpreted as HTML.

## Where text belongs

| Content | Source |
| --- | --- |
| Registry, fallback, interpolation, saved-message compatibility | `src/i18n/index.js` and `index.d.ts` |
| UI, questions, rule explanations, battle-log messages | `src/i18n/locales/en.json` and `es.json` |
| Canonical Chinese / English card text | `src/cards/catalog.json` |
| Spanish card text, keyed by stable card ID | `src/i18n/locales/cards.es.json` |
| Localized card projection (no rules changes) | `src/i18n/cards.js` |
| Glossary labels, explanations and examples | `src/i18n/locales/glossary.{en,es}.json` |
| Historical context summaries | `src/i18n/locales/history.{en,es}.json` |
| Timed help-video captions | `src/i18n/locales/help-captions.json` |
| Language button and checkpoint-safe navigation | `src/i18n/switcher.ts`, `navigation.ts` |

Chinese source phrases are message keys, so existing authored content and old saves remain
readable. New messages should use an explicit key and parameters, not concatenate sentences:

```ts
import {t} from '../i18n/index.js';
label.textContent = t('第 {0} 回合', [turn]);
```

Add the same key to every message catalog and preserve all `{0}`, `{1}`, … placeholders.
Use `text(canonicalMessage)` only at presentation boundaries for old journal entries and
server-generated messages. Its template/composite-clause support is a compatibility adapter,
not a rules parser. New game rules must still operate on IDs and structured state.

`markup()` is only for authored HTML templates. It preserves tags/classes/data IDs and translates
text and accessible labels. Escape dynamic HTML values with the existing renderer's escaping
helper; put arbitrary user input in `textContent`, never through this template helper.

`withLocales()` fills localized map/track names when packs are loaded; it does not mutate the
source scenario or generated map assets. Existing typed UI dictionaries are retained, with
Spanish projections from the shared catalog. Country/card references and colored glossary
terms use stable semantic IDs; translated labels do not become identifiers.

English and Spanish historical popovers currently contain concise summaries, with the original
photos and source links. Help and tutorial videos reuse the map footage with timed localized
titles/captions; small labels recorded inside that footage remain part of the original image.

## Adding a language

1. Register its ID, BCP 47 tag and native label in `LANGUAGES`, its message catalog in `catalogs`,
   and its ID in the exported `Language` type. `Lang` / `Localized` derive from that type.
2. Add matching UI messages and stable-ID card, glossary, history and help-caption catalogs.
   Register these projections in `cards.js`, `terms.js` and `history.js`. Keep rules and numbers
   unchanged. Supply the language entry for the existing typed map/HUD/play dictionaries;
   `translateDictionary` can project those from the central catalog.
3. Check font glyph coverage, card auto-fitting, term word boundaries and longer labels. Latin
   layouts share styles; another script may need its own fonts and text-direction handling.
4. Extend the locale test matrix and run the checks below. There are no translation-service
   calls at runtime, and a missing message falls back to English, then the source phrase.

## Verification

```sh
npm run typecheck
npm run typecheck:worker
npm run test:i18n
npm test
npm run test:online
npm run cards:check
npm run test:audio
npm run build

# Vite must be running at localhost:5173. These create disposable Chrome profiles.
npm run test:i18n:browser
npm run test:i18n:tutorial

# Build and run a local Worker at localhost:8787 first; never points at production.
npm run test:i18n:online
```

Unit checks cover catalog/placeholder parity, card quantities, all glossary/video entries,
escaping and references, and 15 deterministic full games with identical rules states across
languages. Browser checks cover all 330 card layouts, setup, card dragging and a winning move,
language changes during placement, tooltips at phone width, tutorial gestures, and two players
using different languages with reconnect/reload and sealed-headline preservation.
